# 2026-09-02

## "The frame rate feels lower" - measured, and it is not

Taylor felt a drop after yesterday's work. Three candidates in a day: the shader antialiasing, the
geometry extraction, the shared state hook. Built the instrument first, then measured.

- **`FpsMeter`**, on with `?fps` in the URL. Ring buffer of frame intervals, DOM writes through a ref
  four times a second, so it never re-renders the app - a meter that re-rendered every frame would
  read low and be right about it. A query param, not a setting: a `localStorage` key would need a
  reset-all owner for something only ever switched on to chase a feel.
- **`scripts/fps-bench.mjs`**, three modes. The first one I wrote - a hue/saturation drag - could not
  tell the builds apart *and never touched the shader*: the field only repaints on a brightness
  change. So: `bar` drags the Brightness slider and repaints the field every frame; `sync` fires 400
  pointer moves with no vsync between them and reports ms per move.
- Three builds served from `git worktree`s: **A** `979fe90` (before the shader AA and the morph),
  **B** `361c3d4` (geometry extracted, before the hook), **C** HEAD.

| | hue drag | bar drag (shader) | sync, ms/move | bar @ DPR 2 headed | sync @ DPR 2 |
|---|---|---|---|---|---|
| A | 58.8 fps, p95 16.8 | 60.0, p95 16.8, 0 hitches | 0.057 | 114.8 fps, p95 8.5 | 0.041 |
| B | 59.6 fps, p95 16.8 | 60.0, p95 16.8, 0 hitches | 0.056 | 115.2 fps, p95 8.5 | 0.042 |
| C | 58.4 fps, p95 16.8 | 60.0, p95 16.7, 0 hitches | 0.061 | 113.2 fps, p95 8.5 | 0.042 |

Identical within noise on every axis. HEAD holds the display's full refresh at DPR 2 with the field
repainting every frame, and a pointer move costs 42 µs end to end - a quarter of one percent of a
frame. Nothing in yesterday's commits moved the needle.

**Two traps in the measuring, both mine.** The harness servers were piped into `head -5`, which
closed and took Vite with it, so the first DPR-2 run of A crashed. And the preview pane barely fires
`requestAnimationFrame` - the meter read `0 fps / 11577 ms` there, which is the pane, not the app.

The feel is real to the person feeling it; it just is not in these commits under this harness. The
meter is now in both "before" worktrees too, so :5181 and :5173 can be compared in the same browser
with the same eyes.
