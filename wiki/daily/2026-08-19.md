## Window sizing, finally understood

The whole west-edge saga resolved into one root cause and one wrong unit.

`reposition` and `showUI`'s `position` take **canvas coordinates**, not window coordinates. `getPosition` returns both spaces and the code had only ever compared against `windowSpace`, so every attempt to "read here, write there" was mixing units. The real session log made it obvious: asked (280, 72), `windowSpace` came back (1370, 407) — nonsense as chrome offset, entirely ordinary as a canvas pan. Calibration now compares the asked position against *both* readings and adopts whichever holds it.

Then the second unit bug: panel width is **screen pixels**, position is **canvas units**, and those only coincide at 100% zoom. Subtracting a pixel width delta from a canvas x overshot by exactly the zoom factor — the panel grew *and* slid west. `pxToWrite()` divides by `figma.viewport.zoom`.

South-edge chop was unrelated and simpler: it solved backwards through a feedback loop reading `window.innerWidth`/`innerHeight`, which only change once a resize has round-tripped. rAF throttling helped but could not fix it — the loop needed the resize to have *landed*, not merely a frame to have passed. Now open-loop (`startW + travel / HEIGHT_PER_WIDTH`), structurally identical to east and west, which never had the problem.

**Three wrong theories before the right one**, and the turning point was the user telling me to read the docs first. Two of the three would have been avoided by doing that: `reposition` is documented synchronous (killing the "wait for it to settle" theory), and the docs describe `position` and `reposition` as the same setting (which is what makes calibration possible without moving anything).

## What Figma owns now

Researched rather than assumed: Figma has **no native resize handle and no docking**, and even `create-figma-plugin`'s standard `useWindowResize` does its own drag detection over the bottom and right edges only. So the resize machinery stays — ours is a superset.

Placement was the opposite. Tested by omitting `position` entirely: the panel opened sensibly and reopened where it had been moved to. **Figma persists window position itself**, so the stored `windowPos`, its restore path and `moveToWindowPoint` were all duplicating the host — deleted, 125 lines out. Calibration now dictates a position on the first run only and caches the detected space, so no later launch overrides Figma's memory.

Lesson worth keeping: before building window management, check what the host already does. Two of the four things being maintained here were the host's job.
